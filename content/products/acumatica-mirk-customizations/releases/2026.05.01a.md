# Acumatica ~ MIRK.Customizations Release Notes

Comparison: `2026.05.01 to 2026.05.01a`  
Build: `25.201.0213`

## Features Overview

The 2026.05.01a package updates MIRK.Customizations from 2026.05.01 to 2026.05.01a.

- Improves DocuSign placement for PI-related signature fields so PI name and PI date fields appear only when the optional PI signature is used.
- Sets PI name and PI date fields to DocuSign-managed values, helping the envelope use the signer name and signed date from DocuSign instead of requiring manual entry.
- When signing order is enabled, automatically places the current Acumatica user first in the signer order when that user's contact has an email address.

## Features Removed or Altered

No user-facing features were removed.

DocuSign auto-place behavior was altered for PI-specific fields:

- `pisign` is treated as an optional signature trigger.
- `piname` is forced to DocuSign's full-name tab type.
- `pidate` is forced to DocuSign's date-signed tab type.
- `piname` and `pidate` are conditionally shown after the recipient uses the matching `pisign` tab.

#### Code-Level Changes

- Seeds new auto-place defaults for `pisign`, `piname`, and `pidate`.
- Changes auto-place setup matching so existing defaults are found by `AnchorPrefix`, allowing corrected tab-type metadata to update existing records.
- Adds `ConditionalSignatureAnchorPrefix` and `OptionalSignatureConditionalValue` constants for PI conditional visibility.
- Marks the `pisign` auto-place signature tab as optional.
- Applies DocuSign conditional parent labels and values to `FullName`, `DateSigned`, `Text`, and date tabs when the field is conditionally shown after `pisign`.
- Forces `piname` to `FullName` and `pidate` to `DateSigned` even if stored configuration contains another tab type.
- Adds an `isOrder` field-updated handler that seeds the current Acumatica user's contact as signer position `1` when signing order is enabled.
- Inserts the current user as a signer when they are not already listed, or updates the existing recipient to signer type and position `1` when they are already present.
- Reorders the remaining signing recipients to positions `2+`, preserving their previous relative order where possible.
